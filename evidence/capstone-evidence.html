3. Focused Release Check

  • HTML and CSS validation: The W3C Nu HTML Checker reported no errors or warnings for index.html, about.html, meetings.html, and support.html. The W3C CSS Validator reported "Congratulations! No Error Found." for styles.css. All four HTML pages and the shared stylesheet passed validation.
  • Published links and assets: Tested the live GitHub Pages website. All six navigation links opened their intended destinations. CSS styling, images, responsive navigation, and the workshop registration form displayed correctly on the published website. Result: Pass.
  • 320 CSS pixels and 200% zoom: The registration form passed responsive testing at 320px, 768px, and 1280px, as well as 200% browser zoom.
  • Keyboard and visible focus: The registration form passed keyboard navigation and visible focus testing.
  • Form labels, constraints, errors, and recovery: The registration form passed required-field validation, invalid email testing, keyboard navigation, and valid submission testing. Invalid entries were rejected, and the form displayed a demo confirmation after valid fictional information was entered. The classroom prototype does not submit or store registration data or expose it in the URL. Result: Pass.
  • Reduced motion and JavaScript unavailable: Tested the published website at 320 CSS pixels with JavaScript disabled. All six navigation links remained visible and usable. After restoring JavaScript, the responsive Menu button worked normally. Tested prefers-reduced-motion: reduce using Chrome DevTools. All content remained visible and usable, and existing motion was reduced appropriately. Result: Both tests passed.
  • Two current browsers: Tested the published Telepathic Race website in Google Chrome and Apple Safari. Both browsers displayed the website correctly. All six navigation links worked, the responsive Menu button functioned, and keyboard focus remained visible. The workshop registration form displayed correctly, required-field validation worked, and submitting fictional information did not navigate away or expose values in the URL. Result: Pass in Chrome and Safari.

4. Three Findings and Repairs

Finding and condition Impact Repair Exact retest and result
1. Inconsistent Navigation Labels

The Support page still displayed the old navigation labels Workshops, Visit, and Events, while the Home page displayed the updated capstone navigation.

Inconsistent navigation labels could confuse visitors moving between pages and make it harder to locate the About and Virtual Meetings content. Updated the six navigation links in support.html to match the capstone navigation. Set aria-current="page" on Get Support. Opened Home, selected Get Support, and confirmed the Support page displayed all six updated links. The current-page indicator worked, and the Home link returned to the Home page. Result: Pass.
2. Invalid CSS Variable Function

The workshop registration button used vvar(--accent) instead of var(--accent).

The invalid CSS declaration prevented the intended border styling from applying. Corrected vvar(--accent) to var(--accent) in the shared stylesheet. Refreshed the Virtual Meetings page and confirmed the registration button displayed its intended gold border. Validated styles.css using the W3C CSS Validator. Result: Pass.

3. Registration Confirmation Feedback: During testing, the workshop registration form did not display a confirmation after a valid submission attempt. This could leave visitors unsure whether their action was successful. I added a demo confirmation message with role="status" and JavaScript to reveal the message after valid form submission. Retest: Completed the required fields using fictional information and selected Submit workshop registration. The confirmation message appeared: "Demo completed successfully. This is an educational prototype. No registration was submitted or stored." Result: Pass.
